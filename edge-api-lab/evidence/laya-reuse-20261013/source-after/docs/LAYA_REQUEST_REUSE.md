# 本批 Laya 请求复用

相同的用例不需要随着不同大小的 Qwen 重复执行同一次 Laya 决策。领域选择的完整输入相同时可以复用；API 选择由 Qwen 选定的领域和候选约束，只有完整请求相同时才复用。

请求身份包含用户原文、可信对象类型、Qwen 所选领域、候选的标识/描述/顺序、模型、语言和输入预算。部署 namespace 固定 Laya 版本、权重 revision、CPU 线程及服务配置。候选顺序会影响原生 tournament，不能只按用户原文或候选集合做无序缓存。

缓存只保存完整有效的成功原生响应。失败、截断、候选折叠或损坏的来源不能复用。首次响应保持不可覆盖，保留请求/响应 SHA 与来源证据路径和文件 SHA；标准答案不参与构造请求、检索缓存或生成返回值。

返回值中 `x_benchmark_reuse` 区分新推理与复用，保存首次实测计时及来源。复用请求的 `trace.wallMs` 是本次 HTTP 读取时间，不能当成一次新的模型推理。首次客户端耗时、首次原生推理耗时、后续读取耗时分别统计；同一首次结果不会随着四种 Qwen 被重复计入 Laya 推理 P50/P95。

API 的准确率仍可按各 Qwen 的候选范围进行配对：同一原生结果在相同候选下复用；候选不同时是新的 Laya 决策。领域准确率优先按唯一用例统计。上述对照仍不是 Laya 独立端到端任务成功率，填参和执行请求始终由 Qwen 决定。

本次切换保留此前全部正式证据，只继续尚未保存的 Qwen 案例，不修改 Qwen 提示词、参数、领域/API 检索、评分或用例。服务缓存政策变更单独登记。已有历史重复实测保留为重复测量，不伪装成缓存命中。

缓存减少 Laya 与 Qwen 的 CPU 竞争。因此切换前后、不同 Qwen 模型的耗时包含资源条件变化，只可观察流程耗时，不能把变化全部归因于模型大小。原批评测页面里的 Laya wallMs 汇总是 HTTP 请求耗时；模型推理与缓存访问的分离结果以复用专项报告为准。

缓存默认关闭，只为显式配置绑定的运行中批次开启。批次结束或配置撤销后普通 Laya 实验按原生方式执行。配置、seed、持久缓存、来源快照和切换日志位于本项目的 `data/runtime` 与 `evidence`，不需要 API key。
