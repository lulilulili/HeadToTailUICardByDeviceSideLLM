# 端侧语义 API 验证台

当前及未来一段时间为可行性验证阶段。第一阶段只处理一个领域、一个 API 的单服务请求：中文提示词 → 领域 / 字段或操作 API → 显式参数 → 原文核对 → 系统补全与时间归一化 / 精度降级 → 模拟回执。当前 10 个领域共 417 个伪 API，包含原六领域以及设备状态、网络连接、位置服务、音频媒体。回执显示输出契约与字段投影，真实值为 null；组合服务留待第二阶段。

## 当前阶段导航（2026-10-11）

默认题组为 `single-service-100-v1`：10 个领域各 100 条，共 1000 条中文单服务用例。原 100 条开发用例与新增 900 条分别统计；原小题组和历史 478 条独立保留，服务总语料 1578 条。跨服务/组合服务不在本轮范围。优先查看批量评测的“千题单服务实测”和详细说明首个“当前可行性验证”页签，其他 13 个说明页签标明历史快照。

本轮按 1.5B → 3B → 0.5B 串行各运行 1000 条，计划 3000 条正式调用，7B 不参与。实时报告为 `docs/single-service-100-v1-results.json`，独立原始证据在 `evidence/single-service-100-v1/`；网页读取实际进度，未跑模型不算 0 分。评测期间工作台禁止发起其他调用，以免改变推理条件。入口 `npm run benchmark:single:100`，只初始化冻结清单可附加 `-- --initialize`，只重导出已有证据可用 `-- --export-only`。同一冻结条件恢复已保存 key，不覆写正式原始记录；代码/语料/模型 digest 改变时拒绝混合版本恢复。

本轮覆盖 248 个不同伪 API（目录共 417 个），不是全 API 穷举或人类独立盲测。模型原始参数与工程后完整语义分列；正确澄清/解析失败不能等同执行成功，期望可执行的 901 条另有指标。77 条预期澄清、22 条预期解析失败，以及 20 条已知时间解析/夹具边界明确披露。手机位置、时钟、网络句柄及音频场景均采用固定实验 fixture，不读电脑定位。

当前版本为 `explicit-v7` 提示词、`single-service-v3` 目录、`deterministic-grounding-v2` 原文核对。候选显示字段 / 对象 / 整体查询及允许入参，并补充参数语义；模型先保留本句明确值，代码再核对原文字串及缺失信息，最后读取可以补全的系统参数。原始模型提取与修复参数分开保存，规则不重选 API，也不在运行时读取金标。

当前结果入口为 [阶段说明](docs/current-feasibility.json)、[问题与实测分析](docs/PARAMETER_CAUSE_ANALYSIS.md)、[最终 v2 规则回放](docs/grounding-replay-v2-final3.json)、[本机部分实测](docs/feasibility-final3.json) 及 [全球中文城市专项](docs/global-cities-final3.json)。本机前三档完成各 40 条主样本、12 条提示词对照和 4 条守卫；7B 受硬件限制，整轮按实际记录明确标记部分完成，不虚构缺失成绩。初始推理、final1 / final2 和各版本派生结果、历史 1,200 次输出及 v1 回放保持独立，不覆盖。本轮仍为开发集，缺乏独立盲测、真机执行以及同模型不同量化规格对照。

## 启动

保持 Ollama 运行并准备 Node.js 22 或更新版本，双击工作区的 `启动API验证工程.bat`，或项目内的 `启动实验室.bat`，浏览器自动打开 http://127.0.0.1:3210。重复双击复用已运行服务。停止本项目服务用 `stop.ps1`；故障日志在 `data/runtime/server-error.log`。工程无第三方安装依赖。

已安装四档 `qwen2.5:0.5b`、`qwen2.5:1.5b`、`qwen2.5:3b`、`qwen2.5:7b`，均为 Q4_K_M。当前机器 CPU 为 Intel Core i5-8265U；与历史报告中的机器分开记录。权重存放 `D:\OllamaModels`，用户级 `OLLAMA_MODELS` 指向 D 盘，原 `C:\Users\huzimo\.ollama\models` 通过目录联接指向该目录。选择器仅允许已安装且规格可识别、参数量小于 10B 的本地模型；模型权重不提交仓库。

权重安装不等于本机可顺畅推理：约 8GB 内存的本机运行 7B 时出现内存压力和连续 180 秒超时，因此未完成其当前能力验证。超时是硬件可用性证据，不作为 API 选择或参数抽取能力的 0% 成绩。

## 补全与评测

时间与时区来自 PC 实验环境；本机位置指未来运行应用的鸿蒙手机，当前只使用明确标记的模拟手机位置夹具，不读取电脑定位。城市地理编码为八个城市的固定代表点，并非真实地理编码服务。可切换无位置、粗位置、关闭地理编码或天气数据集，验证降级和失败。日历/联系人/文件/资料等只读查询可用用户选择的当前对象；写目标仍须明确提供。

天气保留请求与生效范围，只按兼容字段/单位降级；严格精度不能满足时要求澄清，当前实况不能冒充未来预测。默认粒度取决于文档对象。官方字段、官方方法、适配契约与业务扩展分开标记。

天气的 `location` 地点原文与 `coordinates` 经纬度是同一个查询位置的替代输入，任选一种即可；都没给时取系统位置。提供坐标时经纬度必须完整，最终解析坐标保留来源和精度。日程参会人/重复规则、联系人网站/群组/关系等复合对象也有具体叶字段入口，数组结果保留多值。

系统读取通过 `systemAdapter.read({capability,field,signal})` 注入，回传数据必须标记 `harmony` 或 `fixture` 来源。当前 PC 没有真实 HarmonyOS SDK / 真机接入；系统时间和明确标记的模拟手机位置按各自来源保留，不冒充鸿蒙真机结果。PC 页面已移除浏览器定位入口，HTTP 位置只接受 fixture。用户已经给出的地点、坐标、时间、网络 ID 或音频流优先；模型遗漏显式值不能作为改用本机默认值的依据。系统读取失败会保留原因，不能虚构当前值。

用户明确地点但没有可信编码时，`system-context` 请求 `location.geocode` 原生依赖；宿主适配器收到的读取参数另含 `arguments:{address:地点原文}`，对应 `geoLocationManager.getAddressesFromLocationName()`。这是解析指定地点，不是读取本机位置。当前仍无鸿蒙宿主接入，八个城市以外的“漠河”等地点未得到可信编码时报告解析失败，不得替换为本机坐标。

地点抽取不查城市白名单。独立采样 60 个带中文名称 / 译名的全球城市（六洲各 10），进行 480 条中文模板回归；其中预先固定 8 城，前三档完成 24 次真实模型调用。专项没有把样本坐标注入天气地理编码夹具：保留地点并正确返回解析失败，不等于已解析出坐标。中文标签条件存在采样偏倚，低人口只是冷门代理。像“我在某地出差，湿度是多少”这样的未核验空间线索会阻止当前位置兜底，要求澄清；“这里”和真正省略地点仍可用系统位置。这里只考虑中文，不评价多语言。

网络能力查询的缺省 `net_id` 由原生依赖 `connection.getDefaultNet()` 获取；它是执行前的系统补参依赖，不是新增组合业务请求。音量查询的缺省 `stream_type` 需要宿主当前音频场景上下文；没有通用原生“当前音频流”getter，既没有用户输入也没有可信宿主上下文时要求澄清，不能默认猜 MUSIC。电量、充电状态、定位状态等零输入查询的数值是 API 输出，不是待补入参，目前仍返回 `null`。

## 历史协议与评测（2026-10-10）

冻结历史评测的提示词为 `sparse-v6`，目录为 `object-fields-v2`，不是当前运行版本。模型仅输出用户明确提供的参数，未知字段省略；没有坐标表达就不提供坐标提取槽，明确经纬度时用坐标替代地点文字。代码补全默认时间、系统位置和策略，并保存来源。分层最多三次调用、意图最多六个候选；一次调用最多十二个候选。运行保留候选、原始消息/响应、每次模型耗时、加载/生成时间和 token 数。兼容旧 null 输出，不用金标改写模型结果。历史默认上下文 2048；当前调用的有效上下文、预算及实际 token 数以每次 trace 为准。

历史有 178 条在 `data/cases.json`，六领域各 50 条、共 300 条在 `data/cases-domain-core.json` 和 `data/cases-domain-other.json`，当时合计 478 条。当前另有 `data/single-service-core.mjs` 的 60 条和 `data/cases-system-single.json` 的 40 条，合计 578 条；当前默认只使用新增 100 条单服务用例。旧 65 条快照在 `data/cases-v1.json`。显式参数、状态、来源和已标注的精度条件共同决定完整计划分数。历史冻结评测时间为 2026-10-10 08:00 Asia/Shanghai。错误保留在分母，预热独立保存，取消保留已完成结果与部分 trace。运行历史及导出存放本机 `data/runtime`。

历史题组 `domain-50-v1` 固定四模型、一次调用模式、每题一次，共 1,200 条模型真实调用；业务执行仍为伪 API，各历史题组不混算。P50 为典型耗时（中位数）、P95 为较慢耗时。完整结果与不同场景的问题来源见 `docs/DOMAIN_EVALUATION_RESULTS.md` 及历史页签“领域模型实测”。该历史题组的首次运行命令为 `npm run benchmark:domains`；已有清单使用 `node scripts/benchmark-domains.mjs --resume`，不会自动覆盖结果或混入改过的用例 / 源码。仅导出用 `--export-only`，不能作为当前默认单服务题组的重测入口。

用户要求优化后重新测试：旧版运行到 548 条时取消，清单及源码快照保存于 `data/runtime/domain-suite-before-alternatives.json` 和 `data/benchmark-before-alternatives/`。新轮使用独立清单，从零开始；用例原文与金标保持不变。候选检索已针对公开诊断用例修复，因此本轮是开发集验证，不是盲测结果。

## 原文核对与执行语义（含 v1 历史回放）

单次运行依次显示模型原提取、原文核对后参数和规则最终参数。`modelArguments`、`extractedArguments` 与原始 trace 保留；确定性修复另存 `groundedArguments`，审计包含原文片段、字符位置、修复或拦截理由。时间归一化在 `resolved.arguments` 和 `resolution.time`。规则不重选领域/API，不读取金标。`grounding.scope` 与 coverage 明确已实现检测范围，未发现问题不代表所有语义已验证。

目标 ID 来源区分原文明确、用户选择、未核实、已拒绝；来源可靠不证明真实对象存在，ID 存在性尚未接真实 SDK。规则核对与解析耗时 `deterministicMs` 与模型每次调用耗时分开记录。

`GET /api/grounding-report` 当前读取 `docs/grounding-replay-v2-final3.json`；逐条审计在 `evidence/grounding-replay-v2-final3-audit.json`。它使用冻结 sparse-v6 的同一 1200 条原始输出，最终执行语义 959/1200（79.92%），相较 v1 的 811 增加 148 条、退步 0 条。没有新增模型调用或改变原模型成绩，不混旧 548 条；回放耗时不是新模型耗时，回执仍为 `value:null`。v1 和初始 v2 报告继续保留。这是公开开发集回放，不是独立留出评测。

验收快照（2026-10-10）：旧严格提取 659/1200（54.9%）、旧严格完整计划 580/1200（48.3%）、旧执行语义 621/1200（51.8%）、核对后执行语义 811/1200（67.6%）。同一冻结输出中改善 190 条、退步 0 条、不变 1010 条；原模型分数不变。规则源码快照为 `data/benchmark-grounding-v1-final/`，报告绑定批次和源码哈希；不匹配时页面隐藏旧结果。

模型容量、契约遵循、相似 API 区分、复制保真、规则干扰和量化影响均须对照验证。历史 1,200 次调用实际最大输入 533 token、上下文 2048，仅一例输出截断；这些历史证据不能说明当前 v7 的 token 使用，也不支持把历史主要问题归因为窗口装不下。四档均为 Q4_K_M，没有量化对照。当前 A/B 与新增十领域单服务结果以独立实测报告为准，不能把规则回放收益当作模型自身改善。

## 验证与边界

运行 `npm test`（并发数限制为 2，仅扫描当前 tests，避免在低内存机器递归运行冻结快照测试）。本轮结论见 `docs/PARAMETER_CAUSE_ANALYSIS.md` 及 final3 报告；`docs/VERIFICATION.md` 和其他 13 个说明页签是历史快照。旧 15 API / compact-v3 的 80 条真实基准保留为 legacy-v1，不能当作新版准确率。

已有推理快照不可覆盖。`npm run benchmark:single` 会核验最初冻结源码，当前源码已经变更时应拒绝复用该快照；不要为重新跑通删除原证据。`npm run benchmark:single:final` 仅回放已保存输出、生成当前 final3 派生报告，没有新模型调用。全球后续新推理用 `npm run benchmark:cities` 的独立 v2 路径；`node scripts/finalize-global-cities-final3.mjs` 仅复用先前 24 条输出。3 条风速金标 API 名拼写修正另有原字段与修正字段审计，不算模型或规则收益。

文件搜索/元数据、服务注册和会议资料为拟定业务扩展，需要未来数据源；官方字段 getter 和字段 setter 需要 SDK 适配器。没有真实读取天气、文件或联系人，也没有写入日程或分享资料。工程暂不支持多意图事务或跨 API 规划，多轮补槽尚未实现；模型仍可能误把多操作请求选成单个 API，原始错误会保留在评分中。本地推理无按 token 云服务账单，但仍消耗时间和计算资源；小样本验证不能替代真实表达的独立留出评估。
