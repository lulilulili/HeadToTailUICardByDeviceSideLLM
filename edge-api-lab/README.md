# 端侧语义 API 验证台

第一阶段：中文提示词 → 领域 → 字段/操作 API → 显式参数 → 原文核对 → 系统补全与时间归一化/精度降级 → 模拟回执。六个领域目前 372 个 API，包含天气、日历、联系人、文件、服务链接和云端业务。所有业务执行均为伪 API；回执显示输出契约与字段投影，真实值为 null。

## 启动

保持 Ollama 运行并准备 Node.js 22 或更新版本，双击工作区的 `启动API验证工程.bat`，或项目内的 `启动实验室.bat`，浏览器自动打开 http://127.0.0.1:3210。重复双击复用已运行服务。停止本项目服务用 `stop.ps1`；故障日志在 `data/runtime/server-error.log`。工程无第三方安装依赖。

已安装四档 `qwen2.5:0.5b`、`qwen2.5:1.5b`、`qwen2.5:3b`、`qwen2.5:7b`，选择器仅允许已安装且规格可识别、参数量小于 10B 的本地模型。

## 页面

实验台、批量评测、能力目录、运行记录、详细说明。说明内有 13 个页签，包含“领域模型实测”和“原文核对与语义”。批量评测内新增“领域与模型对照”，提供领域/模型/场景筛选、准确率与 P50/P95 图表、主错因计数、预期/实际样例和单次调用详情。新增独立“原文核对回放”，对比同一冻结输出的旧严格提取、旧执行语义与核对后执行语义。原模型耗时与规则回放耗时分列，旧实测分数不改。对象字段和输入输出可在能力目录按领域、对象、粒度筛选。

例如“现在湿度是多少”选实况湿度 getter；“明天下午上海湿度”选小时预报；“这份文件叫什么名字”只有明确选择当前文件后才可补 ID。缺创建日程的开始时间、缺写目标或没有合法定位时，不猜关键业务信息。

## 补全与评测

交互读取本机时间与时区；位置为浏览器授权结果或明确标记的实验夹具。城市地理编码为八个城市的固定代表点，并非真实地理编码服务。可切换无位置、粗位置、关闭地理编码或天气数据集，验证降级和失败。日历/联系人/文件/资料等只读查询可用用户选择的当前对象；写目标仍须明确提供。

天气保留请求与生效范围，只按兼容字段/单位降级；严格精度不能满足时要求澄清，当前实况不能冒充未来预测。默认粒度取决于文档对象。官方字段、官方方法、适配契约与业务扩展分开标记。

天气的 `location` 地点原文与 `coordinates` 经纬度是同一个查询位置的替代输入，任选一种即可；都没给时取系统位置。提供坐标时经纬度必须完整，最终解析坐标保留来源和精度。日程参会人/重复规则、联系人网站/群组/关系等复合对象也有具体叶字段入口，数组结果保留多值。

提示词版本 `sparse-v6`，目录版本 `object-fields-v2`。模型仅输出用户明确提供的参数，未知字段省略；没有坐标表达就不提供坐标提取槽，明确经纬度时用坐标替代地点文字。代码补全默认时间、系统位置和策略，并保存来源。分层最多三次调用、意图最多六个候选；一次调用最多十二个候选。运行保留候选、原始消息/响应、每次模型耗时、加载/生成时间和 token 数。兼容旧 null 输出，不用金标改写模型结果。默认上下文 2048，复杂请求可在页面调整。

已有 178 条在 `data/cases.json`，本轮新增六领域各 50 条、共300条在 `data/cases-domain-core.json` 和 `data/cases-domain-other.json`；服务合并为478条可选案例。旧65条快照在 `data/cases-v1.json`。显式参数、状态、来源和已标注的精度条件共同决定完整计划分数。冻结评测时间为2026-10-10 08:00 Asia/Shanghai。错误保留在分母，预热独立保存，取消保留已完成结果与部分trace。运行历史及导出存放本机 `data/runtime`。

新增题组 `domain-50-v1` 固定四模型、一次调用模式、每题一次，共1,200条真实验证；历史题组不混算。P50为典型耗时（中位数）、P95为较慢耗时。完整结果与不同场景的问题来源见 `docs/DOMAIN_EVALUATION_RESULTS.md` 及页面“领域模型实测”。首次执行 `npm run benchmark:domains`；已有清单使用 `node scripts/benchmark-domains.mjs --resume`，不会自动覆盖结果或混入改过的用例/源码。仅导出用 `--export-only`。

用户要求优化后重新测试：旧版运行到 548 条时取消，清单及源码快照保存于 `data/runtime/domain-suite-before-alternatives.json` 和 `data/benchmark-before-alternatives/`。新轮使用独立清单，从零开始；用例原文与金标保持不变。候选检索已针对公开诊断用例修复，因此本轮是开发集验证，不是盲测结果。

## 原文核对与执行语义

单次运行依次显示模型原提取、原文核对后参数和规则最终参数。`modelArguments`、`extractedArguments` 与原始 trace 保留；确定性修复另存 `groundedArguments`，审计包含原文片段、字符位置、修复或拦截理由。时间归一化在 `resolved.arguments` 和 `resolution.time`。规则不重选领域/API，不读取金标。`grounding.scope` 与 coverage 明确已实现检测范围，未发现问题不代表所有语义已验证。

目标 ID 来源区分原文明确、用户选择、未核实、已拒绝；来源可靠不证明真实对象存在，ID 存在性尚未接真实 SDK。规则核对与解析耗时 `deterministicMs` 与模型每次调用耗时分开记录。

`GET /api/grounding-report` 读取 `docs/grounding-replay.json` 的轻量回放报告；逐条审计保存在 `docs/grounding-replay-audit.json`。它使用冻结 sparse-v6 的同一 1200 条原始输出，不新增模型调用、不混旧 548 条。三种评分分别报告，规则回放不能提高原模型提取分数；回放耗时不是新模型耗时，回执仍为 `value:null`。这是公开开发集回放，不是独立留出评测。

验收快照（2026-10-10）：旧严格提取 659/1200（54.9%）、旧严格完整计划 580/1200（48.3%）、旧执行语义 621/1200（51.8%）、核对后执行语义 811/1200（67.6%）。同一冻结输出中改善 190 条、退步 0 条、不变 1010 条；原模型分数不变。规则源码快照为 `data/benchmark-grounding-v1-final/`，报告绑定批次和源码哈希；不匹配时页面隐藏旧结果。

模型容量、契约遵循、相似 API 区分、复制保真、规则干扰和量化影响均须对照验证。实际最大输入 533 token、上下文 2048，仅一例输出截断；主要问题不能据此归因为窗口装不下。四档均为 Q4_K_M，没有量化对照。详细证据与验证假设见页面新增页签。

## 验证与边界

运行 `node --test`；本轮验收与真实模型记录见 `docs/VERIFICATION.md`、页面“实测与验证”。旧 15 API / compact-v3 的 80 条真实基准保留为 legacy-v1，不能当作新版准确率。

文件搜索/元数据、服务注册和会议资料为拟定业务扩展，需要未来数据源；官方字段 getter 和字段 setter 需要 SDK 适配器。没有真实读取天气、文件或联系人，也没有写入日程或分享资料。工程暂不支持多意图事务或跨 API 规划，多轮补槽尚未实现；模型仍可能误把多操作请求选成单个 API，原始错误会保留在评分中。本地推理无按 token 云服务账单，但仍消耗时间和计算资源；小样本验证不能替代真实表达的独立留出评估。
