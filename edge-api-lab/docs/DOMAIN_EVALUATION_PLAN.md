# 六领域 × 四模型验证计划

用户需求：每个领域补充 50 条不同情况的用例，按领域与模型比较耗时、准确率，并解释不同情况下的错误来源。

## 冻结范围

- 在原 178 条用例之外新增 300 条；天气、日历、联系人、文件、服务入口、云端业务各 50 条。新增集标记 `domain-50-v1`。
- 每题保留 testDomain、scenario、category、独特条件说明、显式参数金标与环境；拒识题仍归其测试领域，不能按模型回答的领域分组。
- 本轮固定一次调用 unified，对照 Qwen2.5 0.5B / 1.5B / 3B / 7B，全部已安装且小于 10B；300 × 4 = 1200 条真实结果。
- 温度 0、上下文 2048、一次输出上限 224 token、相同冻结时钟与位置；按模型、领域串行运行，模型预热单独保存。每个领域/模型完成 50 条。
- 每轮开始前冻结语料、模型、目录、提示词及解析代码；启动后不在本轮中途修题或调词。若开发优化后重新跑，必须创建独立清单，不混入此前结果。

## 取消与重新冻结

用户要求先优化工程、再重新测试。旧 `retrieval-v5` 对照完成 548/1200 时取消；已完成结果及冻结源码保存于 `data/runtime/domain-suite-before-alternatives.json`、`docs/validation-domain-50-before-alternatives.json` 和 `data/benchmark-before-alternatives/`。

新轮 `sparse-v6`：未知参数省略；依据文本是否存在坐标、时间和精度策略表达选择允许的输入形式，由模型提取值。地点文字和坐标替代，系统补全仍由确定性代码完成。通用检索修复完整父对象、字段同义词、天气粒度、否定及引用动作词；保留 6/12 候选上限，实际 API 仍由模型选择。原 478 条用例及其金标不变。公开题组的支持题 440 条在两模式离线候选审计均命中，但这只代表召回覆盖。经过公开诊断后优化的新轮结果属于开发集验证，必须另设盲测集检验泛化。

## 指标与诊断

- 每个领域/模型显示实际完成 n/50、领域/API/显式参数/状态/完整计划准确率、P50/P95、服务错误与原始调用次数。未完成的题不伪装为失败或成功；只有完整 50 题后才给最终结论。
- 准确率保留服务/解析错误在分母，预热不计入。时间包括模型推理与规则处理，另存加载、输入、生成、队列和每次调用耗时。
- 主错因互斥并按链路先后归因：服务/结构错误 → 领域错误 → 候选遗漏 → API误选 → 额外参数/缺失参数/参数值错误 → 补全精度/来源错误 → 状态错误。
- 参数错误按具体键保留期待与实际；区分猜默认值或对象 ID、遗漏原文、时间文字改写、类型/数值问题。严格字符串评分的局限需说明。
- 按场景、领域、模型汇总错误数量并附真实例子及 trace 入口。规则分类是依据记录的故障定位，不声称证明模型内部的因果机制。

## 交付与验证

1. 三域各自手工金标、数量/唯一性/场景覆盖/契约/补全一致性测试先 RED 后 GREEN。
2. 纯分析模块测试互斥错因、拒识分组、缺失耗时、部分结果、失败计分与历史不混算。
3. 领域对照视图提供筛选、表图、场景分析、真实案例详情和 JSON 导出；旧评测工作流保留。
4. 启动实际 1200 条统一调用，逐批持久保存清单与结果，可通过页面查看进度。
5. 完成后生成详细报告、页面文档页签，运行必要自动测试并浏览器核验桌面/窄屏与结果详情。

这组是人工设计的诊断语料，每模型单次重复；结论只针对本机、该语料与冻结配置。业务输出仍为伪 API 回执，准确率衡量语义调用计划，不衡量真实天气或联系人数据。
