# 2026-10-13：Qwen 多轮千题与 Laya 并行影子对照

本轮使用昨日原有 1,000 条中文单服务用例（10 领域各 100 条），按 Qwen2.5 0.5B → 1.5B → 3B → 7B 顺序串行运行。共 4,000 个正式案例请求，每题可能产生 1–3 次 Qwen 调用；4,000 不是模型调用总数。预热单独保存，不参与正式分数。

## 谁控制最后的请求

Qwen 使用当前 adaptive-v2：先选领域，简单请求再联合选择 API 与填写参数；复杂请求分别选择 API、填写参数。现有确定性原文核对和系统补全保持原样。

每个领域或 API 选择阶段同时请求本机 Laya，给两者相同的用户原文与候选集合，包含拒识。Laya 使用已有多语言权重和本机 typed choice 适配；输入格式和候选说明仍采用各自提供方的适配，不能解释成只替换模型的纯能力实验。

**仅 Qwen 的返回值控制下一阶段。** Laya 不填写参数，也不决定后续领域/API。API 影子读取 Qwen 选择的领域和候选，而不是 Laya 自己选择的领域。影子失败保留为错误，不替换、重试或失败 Qwen 请求。下一题开始前收齐影子结果，避免不同题的请求混在一起。

## 怎样比较正确率

- Qwen 领域/API/原始参数/最终语义继续使用现有评分，按正式案例计分。
- 影子表单独比较领域和 API 的原始可解析选择（selection），另列完整返回协议有效性（contract）。联合 API＋参数阶段即使 API 选对，也可能因参数结构错误导致 Qwen 主流水线失败；两个口径不可混为一项。
- `all` 以已完成请求为分母，未执行后续选择不算正确；`observed` 只统计真实选择调用；`eligible` 只统计金标在相同候选中的真实调用。候选覆盖与未执行数量同时显示。
- Laya 影子 API 正确率是“给定 Qwen 领域/候选的选择正确率”，不是 Laya 独立端到端业务成功率。千题集没有域外拒识金标，不能用它验证域外拒识。
- 错域造成正确 API 不可见和正确领域内预算漏召回分开统计，不把所有候选漏选都归为检索问题。

## 怎样读耗时

每条 Qwen trace 保存实际起止时间、wallMs、加载/提示处理/生成时间与 token 数。Laya 每个影子保存 HTTP wallMs、作者服务返回推理耗时及完整请求响应；无观测的底层 forward 次数不填造数。

| 时间项 | 含义 |
|---|---|
| 各阶段单次耗时 | 领域、API、API＋参数、独立参数各自的真实请求耗时，含失败 |
| Qwen 每题总时间 | `run.totalMs`，主流水线从开始到完成，含确定性处理，不等待影子收尾 |
| Qwen 模型调用累计 | 所有正式 Qwen trace 的 wallMs 之和，不等于批次墙钟时间 |
| 联合完成时间 | 从本题开始到 Qwen 与 Laya 都结束，包含影子等待 |
| 影子收尾等待 | Qwen 结束后等待本题 Laya 请求完成的时间 |
| 各模型/整批实际时间 | 真实执行窗口，含预热、落盘等开销；跨次暂停不算推理时间，异常窗口截至保存心跳另标 |

页面按模型和领域给出阶段次数、累计、平均及 P50/P95，整题亦独立汇总。预热单列，失败仍计入已完成分母。Qwen `intent_arguments` 同时生成参数，Laya 仅选择 API，其耗时不是等任务对比。

两者并行会竞争本机 CPU。本轮时延标为**并行影子对照条件**；昨日 unified 独占运行可作为端到端观察，但不能把时间差归因于多轮调用或某一个模型组件。

## 固定条件、历史证据与运行

题目、金标、共同题序、模型 digest、量化、fixture 与每次 Qwen 调用设置沿用昨日：num_ctx=2048、num_predict=224、temperature=0、timeoutMs=180000。未指定 num_thread。全局 224 覆盖阶段默认生成预算，本轮不改变这一变量。模拟手机时间仍为 2026-10-10T08:00:00+08:00，上海位置为 fixture，107 题上下文覆写保持原有顶层浅覆盖。

旧基线批次为 `single-service-100-20261012-17ad2cee-68f0-4700-ab84-97cd89343965`。新批次采用唯一目录，绑定源码和语料快照，旧原始记录不改。基线报告和索引的哈希、统计、模型身份与条件核验后嵌入新报告；只有同模型/领域两边样本完整时计算差值，运行中的局部结果不与昨日全量做配对结论。

启动使用 `scripts/benchmark-single-service-100.mjs --new --mode adaptive --laya-shadow --baseline-manifest <旧public-manifest.json> --initialize` 创建冻结清单，再用 `scripts/run-full-benchmark.ps1 -ManifestPath <新清单绝对路径>` 执行。活进程锁、工作台独占门禁、每题首次原子落盘和恢复核验继续有效。运行中禁止修改已冻结源码/提示词/语料/模型与条件；结束后自动离线核验，不发模型请求。

页面“批量评测 → 千题单服务实测”显示当前正式批次和进度。当前状态、精确模型规格、实际电脑环境、Laya revision/驻留及线程以本批 manifest 和页面观测为准，不从配置推造测试成绩。
