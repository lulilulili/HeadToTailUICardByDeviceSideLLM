# 智能分步与官方 Jev

新增 Laya 本机选择 + Qwen 填参，无需 API 密钥或充值；参见 [Laya 本机决策](LAYA.md)。默认 Qwen 智能分步保留，Jev 云端因计费条件当前未使用，适配继续可选。

实验台和手工批量评测默认使用 **Qwen 智能分步（adaptive）**。简单请求通常调用 2 次，复杂输入拆成 3 次。另可选择 **Jev + Qwen**：官方 Jev 云端选择领域和 API，本机 Qwen 提取参数。业务仍返回模拟回执，没有接入手机 SDK 或真实云业务。

## 四种调用方式

| 页面选项 | 完整路径 | 调用次数与用途 |
| --- | --- | --- |
| Qwen 智能分步 | Qwen 领域识别 → API 选择与简单参数提取；复杂时改为 API 选择 → 独立参数提取 | 简单 2 次，复杂 3 次；适合逐阶段检查 |
| Jev + Qwen | 官方 Jev 领域选择 → 官方 Jev API 选择 → Qwen 参数提取 | 有入参通常 3 次；无入参 API 省略 Qwen，实际 2 次 |
| 一次调用（unified） | 一次 Qwen 同时输出领域、API、显式参数 | 历史对照方式 |
| 固定分层（staged） | Qwen 领域 → API → 参数 | 通常 3 次；保留固定阶段对照 |

提前拒识、错误、取消可能使实际次数减少。页面按已保存的调用轨迹计数，失败的已发出请求也保留；不会把计划次数当作成功完成次数。无入参省略适用于 Jev 及 adaptive 的独立参数分支；固定 staged 沿用原流程。

复杂路径由可检查的输入特征触发：明确的 JSON 结构、多个需要写入的字段、写入请求中的多个时间角色或时间范围。若在阶段替换中用 Jev 选择 API，参数必须交给本机模型独立生成。页面显示本次具体原因和实际阶段；这些规则不依赖模型自报 confidence，也没有证明新模式比一次调用更准或更快。

## 模型各自做什么

Jev 使用官方 System One 的 `choice` 问题，在给定候选中选择一个领域或 API。领域问题允许全部已支持领域及拒识选项；API 问题使用所选领域的接口集合及拒识选项。Jev 不在本工程中生成自由文本参数。

Qwen 提取用户明确给出的信息。参数仍经过原文核对、时间与地点规则补全，并保留模型原提取值、校对值与最终参数。确实缺省且契约允许的环境信息才由系统提供；业务目标不猜测。定位 fixture 是模拟手机状态，不是这台电脑的位置，也不是手机真机采样。

“逐阶段替换”允许领域和 API 阶段选择官方 Jev；联合 API/参数、参数提取和 unified 只能使用本机 Ollama。adaptive 界面同时展示简单分支和复杂分支的配置，单次请求只执行其中适用的分支。Jev 模式固定前两阶段为云端 choice，基础 Qwen 模型用于本机填参。旧 `jev-bridge` 仅作内部兼容，不作为页面的官方 Jev 选项。

## 当前 Jev 就绪状态与配置

此前 Jev 适配时用户尚无账号；当前云端计费条件未满足，**尚无真实 Jev 成绩**。本地 SDK 协议测试不能替代云端模型能力测试。“已配置”只表示后端读到配置，凭据有效性仍须通过实际请求验证。

密钥未配置时，页面会说明原因并拦截提交；当前是否读到配置以刷新后的后端状态为准。

先打开 [TypeSafe 官方控制台](https://console.typesafe.ai)，完成注册或登录后，按官方控制台提示获取 API 密钥。当前登录页提供 Google 或邮箱入口；登录后的操作以控制台实际提示为准。[官方快速入门](https://docs.typesafe.ai/introduction/quickstart)也将密钥获取入口指向该控制台。

1. 使用 Node.js 22 或更高版本，在工程目录安装锁定依赖：`npm ci --ignore-scripts`。工程锁定官方 `@typesafe-ai/sdk` 0.6.0；首次启动脚本也会检查和安装依赖。
2. 获得官方账号和密钥后，可双击工程的“配置Jev.bat”，或复制 `.env.example` 为 `.env`，在本机填写 `TYPESAFE_API_KEY=你的密钥`。也可设置同名系统环境变量；已有进程环境优先于 `.env`。
3. 默认模型为 `jev-latest`；如需更改，在后端配置 `JEV_MODEL`。重启工程后点击页面“刷新状态”。
4. 选择 Jev + Qwen，或只替换领域/API 阶段。尚未就绪时运行按钮不可用，提交也会被拦截；仍可用默认 Qwen 方式测试。

密钥只由本机后端读取，不进入浏览器配置、提示词、请求详情或导出记录。页面的官方请求 JSON 展示状态、模型和问题，不展示认证头。官方云端需要网络，可能产生费用；本机 Ollama 无按 token 云服务账单，但仍消耗本机内存、电力与计算时间。费用以官方账号信息为准，本说明不猜测价格。

## 如何读一次调用

页面展示实际请求总耗时、实际模型、请求模型、输入/输出 token，以及官方 typed answer、概率分布、confidence、usage、问题标准与输入状态。**confidence 不是正确率**，概率也不是这组开发集上的准确率，更不能证明最终参数或业务结果正确。

官方 API 不提供加载、提示处理、生成分段耗时或生成速度，本工程显示“—”，不从总耗时推算这些值。Qwen 的分段数据来自 Ollama。链路总耗时另含规则核对与补全，不能把两者混为一次模型调用。

缺密钥、认证错误、限流、超时、取消或响应结构错误会明示并保留失败轨迹；本工程关闭 SDK 隐式重试，也不会静默切换为另一个提供方。应先排查相应原因，再由用户另行重试。

## 新评测与历史证据

已完成的 **4,000 条 unified** 是四档 Qwen 的一次调用历史基线，原始记录、冻结源码和审核独立保留；不代表 adaptive 或 Jev 的分数。新模式的手工评测另建批次，不覆盖该历史报告。

这是公开开发集上的有限领域、单服务验证：固定 fixture、一次案例一个 API 计划、字段直达、业务模拟。严格原始参数评分与最终执行语义评分分开；后者不能等同真实业务完成率。比较不同调用方式时，应使用相同案例、上下文和模型设置，分别报告实际调用数、总耗时与分阶段耗时；Jev 准确性及云端耗时留待有效账号配置后的独立评测。

当前 adaptive / Jev 提示词为 adaptive-v2 / jev-choice-v2，路由策略为 adaptive-routing-v1；先前 v1 smoke 保留为历史记录，不改写为新版本结果。
