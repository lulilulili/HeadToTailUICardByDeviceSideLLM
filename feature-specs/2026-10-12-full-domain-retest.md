# 全领域四模型重新测试实施计划

**Feature:** 用户授权的全领域重测与测试环境标注。
**Goal:** 同步远端最新实现，修正仍可复现的云端参数规则问题，以固定千题语料对四模型重新启动完整、可恢复的真实推理，并在页面展示真实 PC 测试条件。
**Acceptance Criteria:** 10 个领域各 100 条；Qwen2.5 0.5B → 1.5B → 3B → 7B；共 4,000 次正式调用；预热单列；固定原文、金标、环境 fixture 和推理参数；原始提取、最终执行语义与每次模型耗时独立记录；环境与实际模型 offload 可核验；旧记录保留；运行可恢复且禁止重复并发；已启动的批次在结果页可查看进度。
**Architecture cell:** 当前独立 Node 验证工程，无额外架构归属文件。
**Map delta:** none。
**Map delta why:** 沿用注册目录、pipeline、千题 runner、只读报告与证据核验接口。

## 基线与范围

- 远端基线：50dffc4，原有 563 项自动检查通过。
- 当前代码已包含 sparse-v7、deterministic-grounding-v2、10 领域及 1,000 条单服务用例；不重复实现远端已有的参数处理。
- 用户明确覆盖文档原“7B 不参加”限制，本轮四模型、4,000 次。
- 不修改题目、金标或评分定义；不在推理过程中修改模型提示词与规则。不新增真实 Harmony SDK 或组合业务执行。
- 原始测试 fixture 时间仍为 2026-10-10T08:00:00+08:00、Asia/Shanghai；发布日期与 PC 环境采样日期为 2026-10-12。

## 最终合同

- `manifest.conditions.models` 是本轮模型集合与顺序的权威记录，`totalCalls = corpus.total × models.length`。
- 历史三模型 manifest 保留 3,000 计划数；新四模型 manifest 使用 4,000，页面与离线核验按各自 manifest 阅读。
- `conditions.hardware` 保存实际 PC 处理器、核/线程、内存、OS、架构；模型 digest、量化、Ollama/Node 版本和推理参数绑定批次。
- 推理前后保留 CPU/内存采样及实际 Ollama 运行状态；未知 GPU/offload 信息标记未知，不由显卡型号推断。
- 伪手机位置、时钟、网络、音频等 fixture 与实际 PC 测试硬件分开呈现。

## 实施与验证

1. 对可选关联 ID 的错误阻塞先补失败回归检查，再修正，保留拒绝假 ID 的审计与必要目标澄清。
2. 将千题模型集合、报告分母和审核约束适配为四模型，同时验证历史三模型兼容性。
3. 更新页面与说明文档，展示动态模型顺序、进度和测试环境；没有实测分数时不显示虚假零分。
4. 在隔离 worktree 中运行完整自动检查和千题静态合同验证；做独立审核。
5. 冻结源码与语料，更新主工程并重启新服务，确认 417 API、10 领域、千题页和独占门禁。
6. 初始化独立新批次并启动 runner；确认真实模型调用、完整 trace 与持续落盘，保存本轮启动及环境记录。

## 状态对象与不变量

| 对象 | 唯一 owner | 转移 / 事件 |
|---|---|---|
| benchmark manifest | 千题 runner | queued → running → completed；异常为 failed/interrupted；恢复先核对源码、语料和模型 |
| runner lock | 千题 runner | 原子创建；已有活进程拒绝；死进程留存 stale 记录后再接管；仅 owner 释放 |
| 原始单次记录 | 当前 manifest | 原子首次写入；存在不覆盖；恢复按模型/用例 key、原文字段和 SHA-256 校验 |
| 报告 / index | manifest 的只读投影 | 以已保存记录生成；空分母 null；未完成不计零分；全量完成才宣称 completed |
| 工作台独占门禁 | HTTP application | 读 running manifest 判定；接受请求前和推理前都检查，避免排队请求争抢 |

- INV-1：不能把三模型历史结果作为四模型结果；动态分母测试覆盖。
- INV-2：题组每域 100 条、共 1,000 个唯一 ID；静态合同与固定题序检查覆盖。
- INV-3：正式一题一次 trace，预热不进入分数；完整离线核验覆盖。
- INV-4：进程中断后保留已保存记录；源码/模型变化拒绝恢复；lock/index 恢复对抗测试覆盖。
- INV-5：错误调用留在已完成分母，模型原提取与规则结果不混淆；报告及评分检查覆盖。
- INV-6：假可选 ID 删除后不能新增无关必填目标；回归检查覆盖，必需写目标仍应澄清。
- INV-7：PC 硬件数据与手机 fixture 分开，offload 只来自实际采样；环境展示测试覆盖。
