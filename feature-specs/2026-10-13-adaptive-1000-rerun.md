# Qwen 多轮千题重测实施计划

**Feature:** 用户授权的 Qwen adaptive 四模型重测。
**Goal:** 沿用 2026-10-12 的 10 领域 × 100 条语料，按 0.5B → 1.5B → 3B → 7B 执行当前 adaptive 路径，保存每一阶段与完整请求的准确率和耗时，独立显示并比较一次调用基线。
**Acceptance Criteria:** 4,000 个正式案例；相同语料、固定题序、fixture 和推理参数；简单两次、复杂按需三次；预热单列；所有实际模型尝试含失败均记录；可恢复、冻结版本、禁止并发；页面显示模式、案例数与实际调用数，原始提取和最终语义分开计分；历史证据不变；实际启动并验证持续落盘。
**Architecture cell:** 独立 Node 验证工程，沿用千题 runner、report 和只读评测页面。
**Map delta:** none。
**Map delta why:** 扩展既有批次合同和多阶段统计，无新业务服务。
**Architecture:** 新批次显式声明 mode=adaptive；旧批次缺省 unified。以 run.traces 记录实际调用，报告按案例计准确率、按完整链路计延迟，补充分阶段耗时和调用数。沿用独立存储、原子首次写入、恢复核验和工作台独占门禁。
**Tech Stack:** Node.js、Ollama、Qwen2.5、PowerShell、现有浏览器页面。
**前端验证:** Yes，实时千题页展示独立批次与实际阶段。

## 固定测试条件

- 本轮模型四档均已在本机安装；名称、digest、量化与硬件以新 manifest 实际采集绑定。
- 题目、金标、题序、模拟时间 2026-10-10T08:00:00+08:00 和上海 fixture 沿用昨日基线。
- num_ctx=2048、num_predict=224、temperature=0、timeoutMs=180000 保持不变；不增加重试，不修正题目或评分，不修改模型提示词和后处理。
- 本轮每题包含一个完整请求，实际模型调用可能 1–3 次；4,000 是案例数，不能称为模型调用总数。
- 当前千题语料无域外拒识金标，不能据此验证域外拒识能力。无真实手机/业务执行。

## 实施步骤

1. 对 runner 的 mode、恢复核验、多轮 compact 统计先写失败测试，增加显式 adaptive 新批次和模式锁定。
2. 对离线核验先写失败测试，验证合法多轮/跳过/失败前缀以及非法阶段、外部提供方、模型变更和篡改拒绝。
3. 对报告与页面先写失败测试，保持按案例准确率，显示实际调用总数、阶段与完整链路耗时；不把错误领域导致的正确 API 不可见算作候选预算漏召回。
4. 完成必要自动检查及旧基线离线核验；提交并同步主目录，启动新独立批次，冻结依赖与源码。
5. 确认后台真实运行、预热单列、0.5B 正式案例持续写入及页面进度；保留续跑入口。结果完成后执行独立审核与同题基线比较。

## 状态对象与不变量

| 对象 | owner | 状态/事件与边界 |
|---|---|---|
| manifest | 千题 runner | queued → running → completed；异常 failed/interrupted；resume 必须核验模式/源码/语料/模型/参数/context |
| lock | 千题 runner | 原子创建；活进程拒绝重复；死进程保留 stale 后接管；owner 释放 |
| 原始案例 | manifest | 首次原子落盘不覆盖；恢复仅跳过已核验保存 key；未落盘尝试不假称未执行 |
| report/index | 保存原始案例的投影 | 以正式案例分母统计；实际 traces 分别计数；部分批次不显示完整结论 |
| active pointer/HTTP gate | runner/application | 新批次明确切换；旧批次保留；running 禁止额外推理以免影响时间 |

- INV-1：mode 缺省 unified，adaptive 必须显式绑定；非法模式、混模式恢复测试拒绝。
- INV-2：四模型 × 同一 1,000 个唯一 key，冻结顺序；语料哈希及题序测试核验。
- INV-3：真实阶段及失败保留；调用数等于 traces.length，完整延迟取 run.totalMs；多阶段合计、合法前缀及中断测试覆盖。
- INV-4：所有阶段仅同一个声明 Qwen/Ollama；非法阶段、错模型、替换提供方测试拒绝。
- INV-5：历史原始 bytes、57 冻结源码和报告不改；使用历史冻结评分独立离线核验。
- INV-6：新运行期间不得改冻结代码、提示词、评分、参数、模型 digest；变化拒绝恢复和下一模型。

## 对抗验证

- 崩溃窗口：原始文件已写、index 未更新时仅接管严格顺序前缀，并核验原文、期望、上下文和 SHA。
- 并发双写：活 lock 与工作台 gate 阻止另一 runner/手工调用。
- 恢复路径：非法多轮 trace、不同模式、错阶段/模型/提供方和 changed source 均拒绝，不混合批次。
- 旁路读取：错误 active pointer 不读取无关历史；旧报告只作为基线独立展示。

## 用户追加：每次调用计时与 Laya 并行选择

- 领域、独立 API、API＋参数联合阶段、独立参数阶段分别记录实际耗时；记录每题 Qwen 总时间、全部 trace 耗时合计、每模型和整批总时间。预热和错误尝试均保持可核验。
- Laya 作为并行影子选择器，在 Qwen 每个选择阶段读取同一用户原文和同一候选集合。它不填参，领域选择不控制后续 API 候选；API 对照使用 Qwen 选中的领域与候选。
- 仅 Qwen 返回值控制后续 pipeline；影子失败不能失败/重试/替换 Qwen。下一题前收齐影子，记录 Qwen 主链路时间、额外等待及联合完成时间。
- 影子单列领域和 API 的选择正确率、合同成功率、候选覆盖、调用次数和耗时。API＋参数的 Qwen 联合任务与 Laya 纯 API 选择的时间不能解释为同任务速度差。
- 并行推理会竞争本机 CPU，本轮时间标为并行对照条件；昨日独占运行仍可作准确率/端到端观察对照，不作纯结构速度因果结论。
- 影子请求绝不包含测试金标；期望只在响应完成后用于评分。所有原始 Laya 请求/响应、错误和模型驻留信息独立保留。
- 对抗测试新增：延迟/失败的影子不控制或阻塞 Qwen 下游；无调用阶段不凭空评分；两者候选严格一致；篡改选择/耗时/期望/候选与错提供方拒绝离线认证。
