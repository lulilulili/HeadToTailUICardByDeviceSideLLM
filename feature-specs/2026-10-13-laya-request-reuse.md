# Laya 完整请求复用

用户要求：相同的千题不应随 0.5B、1.5B、3B、7B 各重复执行一次 Laya。保留 Qwen 为主链路，分开统计模型推理与缓存读取耗时。

实现范围：在本机 Laya 服务侧显式启用当前批次的完整请求缓存，不修改本批冻结的 Qwen 提示词、领域/API 候选规则、填参、评分、用例、runner 或已保存证据。领域输入相同时可直接复用；API 输入包含 Qwen 选定领域和候选，只在完整请求相同时复用。候选顺序会影响 tournament，因此顺序也属于请求身份。

1. 先用合成数据验证请求键、候选变化、失败/截断不缓存、来源校验、并发去重及计时分离。
2. 从已保存的有效 Laya 原生请求/响应制作首次结果 seed，保留原文件 SHA、首次客户端耗时和原生推理耗时。评分答案不进入请求键或缓存响应。
3. 仅在显式缓存 namespace 内复用，namespace 固定 Laya 版本、模型 revision 和部署参数。命中响应携带来源标记；实际读取耗时与首次实测耗时分列。
4. 验证隔离工作区后部署不在冻结 closure 内的服务文件。切换前保存当前执行状态；只恢复未保存的 Qwen key，已保存结果不覆盖。
5. 记录服务政策切换与执行恢复。缓存减少 CPU 竞争，切换前后的 Qwen 耗时不能当成仅由模型大小导致的变化。
6. 独立生成复用计量说明及报告，区分历史重复实测、首次推理、缓存命中及不同候选的新推理。冻结批次原报告保留，以原始响应中的标记补充解释。

验收：相同原生请求后续不调用 Laya；候选/领域/顺序/预算/模型变更不能误复用；无缓存读取时间冒充模型推理时间；Qwen 全部四个模型继续执行且已有正式证据 SHA 不变。
